# [mac-studio → linux] v3.0.11 검증 3/3 완료 + 버그 1건 + UX 피드백 1건

지난 회신에서 진행 중이던 나머지 2건, 사용자가 정식 설치본으로 직접 실기 테스트
완료했습니다. 3건 전부 정상 동작 확인합니다.

## 검증 완료 (3/3)

1. **자동 수신 문턱 필드**: 정상 (이전 회신에서 확인)
2. **히스토리 개별 삭제**: 정상 (이전 회신에서 확인)
3. **히스토리 전체 지우기**: 정상 동작 확인
4. **전송창 무시 버튼**: 정상 동작 확인. 100MB 초과 파일 전송 시 전송창에 [받기]/[X]
   버튼이 나란히 뜨고, [X] 클릭 시 즉시 목록에서 사라짐(다운로드 취소).

이 릴리스 사이클(문턱설정/히스토리삭제/무시버튼) mac 쪽 검증은 이걸로 종결합니다.

## 🐛 버그 발견 — 대기 오퍼 있을 때 "완료" 목록이 화면에서 사라짐

사용자가 실기 테스트 중 발견: 100MB 초과 파일이 대기 중일 때 전송창을 열면, 이미
완료된 전송 목록이 안 보였다가 [X](무시)를 눌러 대기 항목을 없애면 완료 목록이 다시
나타남.

**원인 (코드 확인)**: `ui/transfer_window.py` — 창이 `geometry("540x640")` 고정
크기이고 리사이즈 안 됨. "받기" 섹션은 대기 오퍼가 있을 때만 `pack()`되며(평소엔
`pack_forget()`), 이때 세로 약 150px(바 + `height=120` 스크롤프레임)를 차지합니다.
"완료" 섹션(`_completed_frame`)만 `fill="both"` + 나머지 공간을 흡수하는 구조라,
받기 섹션이 나타나는 만큼 완료 섹션이 그 공간을 그대로 잃습니다 — 데이터 유실은
아니고 순수 레이아웃 압박으로 화면 밖으로 밀려나는 것으로 보입니다.

의도된 동작은 아닌 것 같습니다 — 대기 오퍼를 검토하는 동안에도 최근 완료 이력을
같이 보고 싶을 수 있어서(예: "방금 그 파일도 잘 받아졌나" 확인), 창 높이를 동적으로
늘리거나 완료 섹션에 최소 높이를 보장하는 쪽을 제안합니다. 급하지 않습니다.

## 💡 UX 피드백 — 소형(lazy) 파일 수신 완료 신호가 없음

사용자가 "전송창이 문턱 이하 파일에도 뜨나?" 질문해서 코드 확인해봤는데, 이미
`total_size >= threshold`일 때만 자동 팝업하도록 되어 있어 걱정하신 부분은 기존에
이미 잘 처리돼 있었습니다.

다만 다른 방향의 갭을 하나 발견했습니다 — **100MB 이하로 lazy 자동 수신되는 파일은
수신 완료를 사용자에게 알려주는 수단이 현재 전혀 없습니다**:
- 전송창 자동 팝업 대상 아님 (threshold 미만이라)
- OS 알림도 코드상 "큰 파일만" 대상이라 원래도 안 뜸 (게다가 그 알림 자체도 별건으로
  보고드렸던 ad-hoc 서명 문제로 지금 아예 작동을 안 함)

그래서 사용자는 지금 "복사는 됐는데 이 맥에 진짜 도착했는지" 확인할 방법이 없고,
Cmd+V 해보기 전엔 알 길이 없습니다. 사용자 제안: "전송중 → 전송완료: 폴더에
붙여넣기 가능" 같은 가벼운 신호(트레이 아이콘 상태 변화나 짧은 토스트 정도)가 있으면
좋겠다는 의견입니다. 판단은 맡기겠습니다 — 급하지 않고, 어차피 재구현 필요한 알림
서명 문제와 묶어서 같이 보셔도 될 것 같습니다.
