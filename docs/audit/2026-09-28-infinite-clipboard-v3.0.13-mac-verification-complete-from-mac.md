## 사용자 UX 제안 — 결정은 그쪽에 맡깁니다

### A. 맥에서 큰 파일(받기 모드)이 대기 중이라는 신호가 사용자에게 닿지 않았다 — 붙여넣기를 했다가 엉뚱한 텍스트 파일을 받았다

사용자 관찰: 작은 파일은 붙여넣기 단축키로 바로 붙었는데, 큰 파일은 붙여넣으니 **텍스트 파일이 대신 생겨** 전송이 안 된 줄 알았다가,
트레이 → 파일 전송에서 [받기] 버튼을 찾아 받았다. 사용자 제안: **큰 파일일 때 붙여넣기를 하면 전송창을 띄우거나, 받을지 확인창을 띄우기.**

맥 쪽에서 확인한 기전:
- 받기 모드 offer(21:58:18, 22:09:55) 도착 시 **맥 클립보드는 바뀌지 않습니다**(그 시각 `텍스트 클립보드 설정` 로그 없음) — 설계대로(`main.py` 받기 모드 주석,
  받는 PC 가 클립보드를 소유하지 않음). 그래서 붙여넣기는 **직전에 동기화된 텍스트**를 붙이고 Finder 는 그걸 텍스트 파일로 만듭니다
  (기전은 로그로 확인, «그 텍스트였다»는 추정 — Parsec 동기화가 섞였을 수도 있음).
- 받기 모드의 설계상 신호는 **알림 + 전송창 받기 행**인데, 맥에서는 알림이 닿지 않았습니다. 받기 모드 offer 2건 중
  21:58:18 건은 `알림 전송 실패: No usable implementation found!`, **22:09:55 건은 알림 시도 로그 자체가 없습니다**(실패 줄도 없음 — 왜 둘이 다른지는 모릅니다).
  이 실패 문구는 7월 v3.0.10 때 보고한 것(`2026-07-12-…-v3.0.10-notify-failure-and-threshold-feedback-from-mac.md`
  §1, ad-hoc 서명 추정)과 같고 3.0.13 에서도 그대로입니다(수신 시작·완료 시각 22:10:22 · 22:15:16 에도 같은 실패).
- 트레이 아이콘에도 «받을 항목 대기» 배지는 없습니다 — 기록기상 22:09:55 offer 부터 사용자가 트레이를 연 22:10:13 까지 아이콘 변화 0.
- ⇒ 이번 회차에서 사용자는 큰 파일이 기다린다는 사실을 **전송창을 직접 열고서야** 알았습니다.
근거: 확인한 신호 3종 — ① 알림: offer 시각 로그(21:58:18 실패 줄 1 / 22:09:55 알림 관련 줄 0) ② 트레이 아이콘: 기록기 프레임 22:09:55~22:10:13 변화 0
③ 클립보드: offer 시각에 `텍스트 클립보드 설정` 줄 0. **대기 중일 때의 트레이 메뉴 내용은 보지 않았습니다** — 메뉴에 받을 파일 줄이 이미 있다면 A 의 1번 대안은 절반이 이미 있는 셈입니다.

제안하신 «붙여넣기 순간 창 띄우기»는, 그쪽 코드 주석(함정 #40 — macOS provider 콜백은 진짜 paste 와 Finder 자동 peek 을 구별 못 함)대로
맥에선 오발 위험이 있어 보입니다. 같은 이익(사용자가 대기 파일을 알아챔)을 주는 대안 후보:
1. 받기 모드 offer 도착 시 **트레이 배지(예: 다른 색 점) + 메뉴 줄 `받을 파일: <이름> (<크기>) — 받기`**(클릭하면 받기 또는 전송창). 알림 성공 여부와 무관하게 동작.
2. 맥에서 알림이 실패하면(`is_supported()` False + plyer 실패) **받기 모드 offer 때 전송창을 자동으로 띄우는 폴백**.

### B. 21:58:18 받기 모드 offer(`33a561d7…`)가 기록 없이 사라짐

- 이후 로그 0줄, 22:2x 전송창에도 없음. 사용자는 무엇인지 모릅니다 — 모든 호스트가 클립보드를 공유하니 **테스트 중이던 다른 컴퓨터에서 온 것일 수 있다**고 합니다.
- 코드상 같은 `source_peer` 의 새 offer 가 오면 기존 받기 항목을 조용히 비우므로(`main.py` 1120행 부근 `stale_receivable`), 22:09:55 offer 가
  같은 발신자였다면 그때 지워진 것으로 보입니다(추정). 사용자가 한 번도 못 본 대기 파일이 흔적 없이 사라지는 경로라서, **비울 때 로그 1줄**이라도 있으면 추적이 됩니다.

### C. 클라이언트별로 «어느 호스트와 공유할지» 고르는 설정

- 사용자 제안: 여러 PC 에서 동시에 테스트하다 보니 어느 호스트의 복사가 내 클립보드로 왔는지 알 수 없었다 — **클라이언트 단에서 공유 상대 호스트를 고르는 설정**이 있으면 좋겠다.
- 레포에서 `allowlist|whitelist|blocklist|allowed_peers|share_with|device_filter|target_devices` 등으로 코드·docs 를 찾았는데 해당 기능·기존 요청은 못 찾았습니다(없다는 단정은 아님).
- 참고로 이번 회차에도 맥에서 검증용으로 복사한 텍스트 2건이 다른 PC 들 클립보드로 동기화됐습니다(검증 후 원래 값으로 되돌림).
